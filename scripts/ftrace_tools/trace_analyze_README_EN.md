# trace\_analyze.py: ftrace Data Statistics Analysis and Excel Report Generation

## Tool Introduction

`trace_analyze.py` is an ftrace data analysis tool used to perform **statistical aggregation analysis** on the SQLite DB data generated by `trace_convert.py` and to automatically generate an Excel report containing charts. This tool focuses on **quantitative statistics**, helping developers quickly locate hotspot processes, abnormal scheduling, and IRQ interruption problems from the data dimension.

## Prerequisites

|Dependency|Description|
| ------------ | ----------- |
|Python 3.10+|Runtime environment|
|openpyxl|Excel file generation library|

Install openpyxl:

```bash
pip install openpyxl
```

## Usage Instructions

### Basic Usage

```bash
python trace_analyze.py --input <db_file> [--output <excel_file>]
```

|Parameter|Description|Default|
| ---------------- | ------------------------------------ | ------------------------ |
|`--input`, `-i`|Path of the input db file (generated by `trace_convert.py`)|`ftrace_data.db` (in the script directory)|
|`--output`, `-o`|Path of the output Excel report|`<input>_report.xlsx`|

### Example Commands

**1. Use the default input and output**

```bash
python trace_analyze.py
```

Reads `ftrace_data.db` in the current directory and generates `ftrace_data_report.xlsx`.

**2. Specify the input file**

```bash
python trace_analyze.py -i /path/to/ftrace_data.db
```

**3. Specify the input and output paths**

```bash
python trace_analyze.py -i /path/to/ftrace_data.db -o /path/to/my_analysis.xlsx
```

## Typical Workflow

```text
trace_record.py (collection)
      ↓
trace_convert.py (convert to DB)
      ↓
trace_analyze.py (statistical analysis -> Excel report)
```

1. Use `trace_record.py` to collect ftrace data
2. Use `trace_convert.py` to convert the raw data into SQLite DB format (the default output is `ftrace_data.db`)
3. Use `trace_analyze.py` to perform statistical analysis on the DB and generate an Excel report

## Analysis Metrics

### Process Runtime

|Metric|Description|
| ------------ | ------------------- |
|**Running**|Time the process actually runs on the CPU|
|**Sleeping**|Time the process is in the sleeping (blocking wait) state|
|**Runnable**|Time the process is ready but waiting to be scheduled (scheduling latency)|

### Context Switch

|Metric|Description|
| -------------------------- | ----------------------------------- |
|**cs\_count**|Total number of context switches|
|**cs\_involuntary\_count**|Number of involuntary switches (the process is forced off while still in the Ready state, that is, **preemption**)|

> A high proportion of involuntary switches means that the process is frequently preempted, and CPU binding optimization can be considered.

### IRQ / SoftIRQ Interruption

|Metric|Description|
| ----------- | ------------- |
|**IRQ**|Number and duration of hard interrupts that interrupt the process|
|**SoftIRQ**|Number and duration of soft interrupts that interrupt the process|

> Frequent IRQ interruptions fragment process execution and affect performance stability.

## Output Format

The Excel report contains **4 worksheets** and **3 bar charts**:

### Worksheet 1: task\_summary\_by\_comm

Aggregates the statistics of all PIDs and CPUs by **process name (comm)**.

|Column|Description|
| ---------------------- | ---------------- |
|comm|Process name|
|running\_us|Total Running time (microseconds)|
|sleeping\_us|Total Sleeping time (microseconds)|
|runnable\_us|Total Runnable time (microseconds)|
|cs\_count|Total number of context switches|
|cs\_involuntary\_count|Number of involuntary switches|

**Chart**: Top10 Running Time bar chart (sorted by process name)

### Worksheet 2: task\_summary\_by\_pid

Aggregates the statistics of all CPUs by **process name:PID**. This suits scenarios where the same process has multiple instances.

|Column|Description|
| ---------------------- | ---------------- |
|comm|Process name|
|pid|Process ID|
|running\_us|Total Running time (microseconds)|
|sleeping\_us|Total Sleeping time (microseconds)|
|runnable\_us|Total Runnable time (microseconds)|
|cs\_count|Total number of context switches|
|cs\_involuntary\_count|Number of involuntary switches|

### Worksheet 3: task\_summary

One row per **(comm, pid, cpu\_id)** dimension, without merging. This suits analyzing the behavior of a process on a specific CPU.

|Column|Description|
| ---------------------- | --------------- |
|comm|Process name|
|pid|Process ID|
|cpu\_id|CPU number|
|running\_us|Running time (microseconds)|
|sleeping\_us|Sleeping time (microseconds)|
|runnable\_us|Runnable time (microseconds)|
|cs\_count|Total number of context switches|
|cs\_involuntary\_count|Number of involuntary switches|

### Worksheet 4: proc\_irq\_detail

IRQ / SoftIRQ interruption detail data, showing the interruptions from the process perspective.

|Column|Description|
| --------- | ----------------------- |
|comm|Name of the interrupted process|
|pid|PID of the interrupted process|
|cpu\_id|CPU number where the interrupt occurs|
|irq\_type|Interrupt type (`irq` or `softirq`)|
|irq\_name|Interrupt name / action|
|count|Number of interruptions|
|time\_us|Total interruption duration (microseconds)|

**Charts**:

- Top10 IRQ Time bar chart (sorted by duration)
- Top10 IRQ Count bar chart (sorted by count)

> The X-axis label format of the IRQ charts is `comm:pid@cpu_id`, for example `python3:12345@0`.

## Notes

- **Input dependency**: the input file must be generated by `trace_convert.py` and must contain the `slice` and `thread` tables
- **Compatibility with old data**: if an older version of `trace_convert.py` is used (without the cpu field), the CPU column is empty and the tool prints a warning log
- **Idle process filtering**: the IRQ statistics of the `<idle>` process are skipped automatically
- **Kernel process filtering**: context switch events of kernel processes such as `swapper`, `kworker`, and `migration` are skipped automatically
- **Data volume recommendation**: it is recommended to collect data on no more than 64 CPU cores for about 30s; otherwise the statistical analysis may take a long time
