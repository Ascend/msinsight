# **MindStudio Insight Operator Tuning**

## Description

MindStudio Insight provides the instruction pipeline view, operator source code view, and operator runtime load analysis view to visualize the key performance metrics of operators running on the Ascend AI Processor, helping developers quickly locate software and hardware performance bottlenecks and improve operator performance analysis efficiency.

Based on your tuning objectives, you can refer to the following paths to focus your reading:

- **Determine the operator bottleneck type**: First read the Roofline bottleneck analysis in [Details](details.md#details) to determine whether it is a compute bottleneck or a memory bottleneck.
- **Analyze compute bottlenecks**: Read the compute workload analysis and inter-core load analysis in [Details](details.md#details).
- **Analyze memory bottlenecks**: Read the memory load analysis in [Details](details.md#details) and [Cache](cache.md#cache).
- **Locate high-latency instructions**: Read [Timeline](timeline.md#timeline).
- **Correlate instructions to source code**: Read [Source](source.md#source).
- **Analyze Triton operator memory overflow**: Read [On-Chip Memory](on_chip_memory.md#on-chip-memory).
- **Compare performance before and after optimization**: Read "Supporting Inter-Operator Performance Comparison" in [Details](details.md#details).

## Preparations

**Environment Setup**

1. Install MindStudio Insight first. For details, see [MindStudio Insight Installation Guide](../../install_guide/mindstudio_insight_install_guide.md).
2. Install the msOpProf operator tuning tool. For detailed installation steps, see [msOpProf Installation Guide](https://gitcode.com/Ascend/msopprof/blob/master/docs/en/install_guide/msopprof_install_guide.md).

**Data Collection**

The data for the operator tuning scenario is collected and generated by the msOpProf tool. Select a collection mode based on your actual requirements.

| Collection Mode | Applicable Scenario | Collection Command Example | Generated File |
|-----------------|---------------------|----------------------------|----------------|
| On-Board Collection (msopprof) | Requires real hardware profile data to analyze actual runtime duration, memory bandwidth, cache behavior, etc. | `msopprof --output=./output_dir ./op_executable` | `visualize_data.bin` |
| Simulation Collection (msopprof simulator) | Requires no real hardware or instruction-level detailed analysis, such as instruction pipeline tracing, code hotspot locating, etc. | `msopprof simulator --soc-version=Ascendxxxyy --output=./output_dir ./op_executable` | `trace.json` and `visualize_data.bin` |

> [!NOTE]
>
> - On-board collection requires a real NPU environment. Simulation collection does not require an NPU but requires specifying the chip model (`--soc-version`), which can be obtained via `python3 -c "import acl; print(acl.get_soc_name())"`.
> - The two modes are complementary. It is recommended to use them together: use on-board collection to obtain real profile data, and simulation collection to obtain instruction-level detailed data.
> - For more collection parameters and usage, see the [msopprof User Guide](https://gitcode.com/Ascend/msopprof/blob/master/docs/en/user_guide/msopprof_user_guide.md) and the [msopprof simulator User Guide](https://gitcode.com/Ascend/msopprof/blob/master/docs/en/user_guide/msopprof_simulator_user_guide.md).

**Data Import**

After collection is complete, import the generated profile data files into the MindStudio Insight tool. For details about the data, see [Data Description](#data-description). For data import operations, see [Importing Data](../basic_operations.md#importing-data).

**Constraints**

- In the operator tuning scenario, to import a JSON file into MindStudio Insight, the file must contain the "profilingType":"op" field before the first square bracket. Otherwise, the file cannot be imported. JSON files generated by the msOpProf tool include this field by default. If the import fails, check whether the JSON file content contains this field.
- You can import JSON files by folder. A folder can contain multiple subfolders, but each subfolder can contain no more than one JSON file. Different JSON files must be placed in different subfolders.
- The size of a single JSON file to be imported cannot exceed 1GB.
- Only one binary (`.bin`) file can be imported at a time. The `.bin` files cannot be imported by folder.
- The size of a single `.bin` file to be imported cannot exceed 500MB.
- Only Ascend 950PR&950DT products support collecting instruction pipeline diagram visualization files in `msopprof` mode, with data displayed on the **Timeline** page. For other hardware models, you can collect `trace.json` files in `msopprof simulator` mode and view the instruction pipeline on the Timeline page.

**Terminology**

| Term | Full Name | Description |
|------|-----------|-------------|
| HBM | High Bandwidth Memory | The external main memory of the AI processor, featuring large capacity but high access latency. |
| GM | Global Memory | HBM, the global storage space accessible to operators. |
| L2 | L2 Cache | Located between HBM and AI Core, used to cache frequently accessed data to reduce access latency. |
| L1 | L1 Buffer | The storage space inside the AI Core, shared by the Cube and Vector Compute Units. |
| L0A/L0B | L0A/L0B Buffer | Input buffers of the Cube Compute Unit, storing the left and right matrices of matrix multiplication, respectively. |
| L0C | L0C Buffer | Output buffer of the Cube Compute Unit, storing the result of matrix multiplication. |
| UB | Unified Buffer | The dedicated storage space of the Vector Compute Unit, used for data input and output of vector operations. |
| MTE1 | Memory Transfer Engine 1 | Transfer direction: L1 → {L0A, L0B, UB}. |
| MTE2 | Memory Transfer Engine 2 | Transfer direction: {DDR/GM, L2} → {L1, L0A/B, UB}. |
| MTE3 | Memory Transfer Engine 3 | Transfer direction: UB → {DDR/GM, L2, L1}, L1 → {DDR/L2}. |
| FIXP | Fix Pipeline | Data transfer pipeline, transfer direction: L0C → OUT/L1. |
| Pipe | Pipeline | The execution channels for different types of instructions in the AI Core. |
| Core | AI Core | The compute core in the AI processor, containing compute units such as Cube and Vector. |
| Block | Sub Block | Parallel blocks during operator execution, with each block running on one AI Core. |
