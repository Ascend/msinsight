# MindStudio Insight 启动性能与控制台闪现修复

## 状态与范围

- 用户已批准方案 2：一次性修复四项问题，在一个本地分支中保留独立提交。
- 基线：`origin/msinsight2.0` / `7bd1b5911`。
- 分支：`fix/msinsight2-startup-performance`。
- 不修改、重装或关闭现有安装的软件，不推送远端，不调整知识包格式。

## 证据

安装目录日志最近两次启动中，性能分析后端在 0.15～0.65 秒内就绪，随后等待 AI 服务约 8.68～9.70 秒，才创建主窗口。独立读取已安装资源时，知识包加载和校验约 5.2～5.6 秒；409 个 Bundle 文件导致 ZIP 被打开 410 次、遍历 88,766 个目录项。Node 版本检查缺少 Windows 隐藏控制台标志。Skills 同步每次删除并复制所有一级目录，包括没有 SKILL.md 的 tests 目录。

## 已比较的方案

1. 仅修复控制台、ZIP 和同步：风险小，但完整 RAG 初始化仍阻塞窗口。
2. 上述优化加 AI 服务提前监听、RAG 后台初始化：推荐且已获批准。
3. 全面异步化 Rust 启动及前后端端口状态协议：本次不采用，避免扩大范围。

## 修复设计

### 1. 隐藏 Node 版本检查的控制台

构造 Node 版本检查命令时，在 Windows 设置与其他后台命令相同的 CREATE_NO_WINDOW 标志。保持版本下限、缺失或不支持 Node 的错误状态不变。其他平台不设置 Windows 专属标志。

### 2. 单次顺序读取知识包 ZIP

将已安装知识包的 Bundle 读取改为一次打开 ZIP、顺序遍历。仅读取 bundles/ 下的文件进入现有成员映射，拒绝重复 Bundle 路径并保留读取大小限制；错误或读取完成时关闭流与 ZIP。仍调用现有摘要、文件清单、归属关系、知识库和模型兼容性验证，不增加基于时间戳的校验豁免，不改变 CLI 导入、激活和 verify 的完整性保证。

验收：Bundle 内容与旧实现一致，损坏内容仍被拒绝；目录遍历量随 ZIP 条目数线性增长；针对已安装的 409 文件包测量优化前后耗时。

### 3. Skills 增量同步

仅将包含有效 SKILL.md 入口的一级目录视为 Skill。比较源与目标的文件树和内容，未变化时不删除、不复制；源文件新增、修改、删除或目标缺失、损坏时更新对应 Skill。比较和更新不得跟随目标链接到工作区外，不得删除其他名称的用户 Skill。保留 .claude/skills 链接验证和源与工作区不得重叠的约束，不引入可失效的持久化摘要缓存。

保持 installed 列表表示当前有效的产品 Skill 集合；可额外返回更新、跳过数量用于日志。不自动删除旧版本遗留的非 Skill 目录或用户自建内容。

验收：重复启动目标文件时间戳不变；修改、删除配套文件和修复目标缺失文件有效；tests 不被安装或计数；用户 Skill 保留；链接冲突仍被拒绝。

### 4. RAG 后台初始化，不阻塞主窗口

AI Host 不再在 HTTP 监听前 await 完整 RAG 初始化。通过后台 Worker 持有原有 RAG 服务和 ONNX 会话，将大 JSON 解析、校验和推理与 Host 事件循环隔离。Host 使用稳定代理提供 isEnabled、getStatus、retrieve 及关闭方法；构建脚本将 Worker 作为独立入口打包，确保源代码运行与产品包运行均可定位入口。

保留工作区准备在 ACP 子进程启动之前完成的既有约束；端口和 capability token 协议不改。HTTP 开始监听后启动 RAG Worker，不要求 Rust 或主界面等待 RAG。状态区分 initializing、ready、disabled/failed；初始化中知识库调用返回明确的 initializing，不提供未经校验的结果。AI 面板能展示知识库加载状态，完成或失败时更新，而不是误报整个 AI 后端无法连接。

failOpen=true 时记录稳定错误原因并禁用 RAG，其他功能继续；failOpen=false 时通过已有 Host 失败关闭路径退出，不吞掉错误。CLI 和 required-smoke 继续直接使用原来的完整初始化与验证流程。

关闭时终止 Worker，结束待处理调用；初始化失败、Worker 异常退出和监听失败均不得留下未处理 Promise 或后台线程。增加启动阶段耗时日志，不记录 token、用户查询正文或其他敏感信息。

验收：人为延迟 RAG 初始化时，HTTP 状态接口和主窗口启动路径不等待；初始化完成后知识检索恢复；禁用、失败、退出和 pending 查询清理有测试覆盖；打包产物具备可运行的 Worker。

## 提交与验证计划

设计文档单独提交，产品修改按以下四个提交组织：

1. Windows Node 检查不弹控制台，补平台回归测试。
2. 知识包 ZIP 单次读取，补成功、重复条目、损坏和流错误测试。
3. Skills 增量同步和有效入口筛选，补重复启动、更新、损坏及安全边界测试。
4. RAG 后台初始化、状态、清理、独立打包入口及集成测试。

按现有 node:test、前端测试与 Rust release 测试入口验证；必要的临时文件放在已批准的 OpenCode 临时目录或测试 fixture 目录。使用已安装资源时只读取，不写回。记录实测结果与无法执行的验证，不把单元测试结果当作完整 GUI 或安装包验证。

## 明确不做

- 不关闭安全校验，不凭 mtime 判定知识包可信。
- 不实现知识包格式迁移、自动下载或自动升级。
- 不改安装路径、权限、WebView2 缓存或显卡设置。
- 不处理未被用户观察到的主窗口白闪，也不进行无关架构重构。
